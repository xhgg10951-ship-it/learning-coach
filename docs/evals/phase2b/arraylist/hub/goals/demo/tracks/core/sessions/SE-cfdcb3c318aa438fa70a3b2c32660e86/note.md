### explanation-10 · AI 判断

用搬书类比、翻倍教学模型说明100次写入加127次复制；一般地复制总量<2L<2n，总工作<3n，平均受固定常数约束。强调教学序列非实际ArrayList容量序列、单次最坏与均摊可并存、几何增长前提以及尾部单项追加范围。

引用与摘录：

- conversation/assistant/10
  > 先把它想成搬书：每放一本书要做一次工作；书架满了，换大书架时还要搬旧书。某次搬家很贵，但判断均摊成本要看“到目前为止一共做了多少工作”。
  > 
  > 为看清总账，先用**容量每次翻倍的教学模型**，不是实际 ArrayList 容量序列。容量从 1 开始，连续追加 100 个元素：
  > 
  > 1. 写入新元素，一共 100 次。
  > 2. 扩容时复制旧元素，依次复制 1、2、4、8、16、32、64 项。
  > 3. 复制总数是 127，合起来是 227 次基本工作；平均每次追加约 2.27 次。
  > 
  > 关键不是这个例子的平均值恰好比较小，而是：**追加数量再大，总工作量也不会超过追加数量的某个固定倍数。**
  > 
  > 设最后一次扩容复制了 L 项。此前复制量倒着看是 L/2、L/4、L/8……，所以全部复制量小于 2L。发生这次扩容，说明至少已经追加了 L+1 个元素，因此 L < n，其中 n 是累计追加数量。
  > 
  > 于是：
  > 
  > ```text
  > 全部复制工作 < 2L < 2n
  > 全部新元素写入 = n
  > 总工作 < 3n
  > 平均工作 = 总工作 / n < 3
  > ```
  > 
  > 这里的 3 不会随着 n 变大而变大，这就是“固定上限”。O(1) 表达的是这个增长关系，并不表示每次实际耗时相同，也不要求平均值恰好等于某个数字。
  > 
  > 例如第 65 次追加会复制 64 项，再写入 1 项，单次工作量是 65；但从第一次到第 65 次的总账，仍然受上述固定倍数约束。**单次最坏 O(n) 与均摊 O(1) 可以同时成立。**
  > 
  > 几何扩容的作用就在这里：越早的搬家规模越小，所有搬家合计仍与最终元素数量成正比。若每次只多开一个位置，复制量就会变成 1+2+…+(n−1)，总量是 O(n²)，平均每次则是 O(n)。所以均摊常数成本有增长策略的前提。
  > 
  > 这段讨论限定为从空表开始的连续单项尾部追加；中间插入还需要移动后面的元素，批量追加 m 项也要处理这 m 项，不能直接套用单项尾部追加的 O(1)。
