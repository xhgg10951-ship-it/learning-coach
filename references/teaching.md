# 自适应教学

本工作流使用真实对话和 Session 证据决定教学，不预生成题库顺序。AI 解释、示范、反馈；用户决定学什么、学多深、学多快、什么时候停止。

## 开始和恢复

开始教学时先读 `session-context` 和 `teaching-context`。后者返回公共画像、Goal 水平和补充说明、Track 背景、Milestone/Sprint 要求、相关 Session 原始练习、逐项验收证据及教学状态。参数和 JSON 合约见 [teaching-schema.md](../docs/teaching-schema.md)。

- 根据 `teaching_state.source` 恢复上次模式、难度、节奏和拒绝练习选择；用户本轮新指令优先。不把默认 Adaptive 当作每轮重置。
- 根据 `criteria` 的有效证据跳过已有基础。画像、理解反馈只是自报，不能直接升级为验证。`remaining_gaps` 是证据缺口，不是判定用户不会。
- 相关记录未读全时会显示 `history.omitted_sessions`；需要更早证据才增加 `--limit`（最大 100）或用 Session 分页，别把截断当作完整验收。教学状态的显式前序优先于其他较新记录。
- 证据不足时可直接解释、简短询问或一道代表性综合任务。没有固定 5～10 道测试。用户指定知识点就从那里开始。
- 用户已要求开始跟踪学习时按 Session 流程 start/resume。普通答疑或拒绝记录则只在聊天中调整，不为存模式强建 Session。

## 模式与即时调整

| 模式 | 采用的教学方式 |
|---|---|
| Adaptive（默认） | 依据已有证据和当次反馈，选择适当起点、深度与实践形式 |
| Quick | 提炼关键结论、尽早给 Demo 或实际例子，省略已验证的基础 |
| Guided | 对当前卡点逐步提示，让用户选择是否尝试；不把每一步都变成题 |
| Deep | 解释机制、假设、边界与权衡，必要时展开代码或反例 |
| Practice | 围绕目标安排代表性实现、调试、表达或分析任务，再按表现反馈 |

这些是行为偏好，不是 Goal/Sprint 状态。“讲快一点”立即简化并加速；“直接给 Demo”“先不讲原理”直接展示、减少理论；“我不理解，详细一点”对该卡点用 Guided；“深入原理”用 Deep；“给我一道综合题”用 Practice。“今天不做练习”独立设置 `exercise_policy=declined`，不夹带“最后一个小问题”。允许 Deep + fast、Quick + declined 等组合。自然语言由 Agent 理解，不用关键词匹配决定用户意愿。

用户调整时，本轮回答就改变，不先追问“确认切换吗”。已在跟踪学习时，将新的教学状态及来源合并进本轮或紧邻的重要检查点，确保中断后可恢复。记录完整状态，不省略拒绝练习等仍有效选择；用户主动再次要求练习才恢复 allowed。调整理由要引用用户指令或具体作答，不能只写“用户已掌握”。

## 任务、批改和反馈

根据 Sprint 能力要求和当前主题选择实践形式，允许计划外内容：Java 用代码阅读/实现/调试/复杂度分析，MySQL 用 SQL/执行计划/索引分析，英语用表达/改写/情境交流，理论用解释/案例/综合应用。不要统一成口头问答。

优先能同时观察几项关键能力的代表性任务。用户已经给出代码、解释或操作结果时，直接将它作为可验收材料，不要求再答一份相同测试。综合题部分正确时分别保存 `assessment.checks`：已验证能力保留，局部错误不会让整组从零开始。

- 答得好：指出哪些能力已有证据，减少基础提问，提高应用或迁移程度。连续正确是加速信号，不设答对 N 题的门槛。
- 概念/推理错误：准确指出错误与原因，只解释相应缺口，用必要的小例子辅助；不要重讲整个领域。允许用户不改错就结束。
- 措辞问题：若语义和应用正确，简短修正术语，记为 `wording`，不据此判定概念未掌握或进入长篇补课。按用户本次明确的变量定义、假设和等价推导判断，不能沿用题干中同名符号的旧含义误判；已明确且等价的表达无需换符号再答。可选延伸尚未作答可单列未验证，不抹掉已经证明的对应能力。
- AI 演示的运行结果不能充当用户独立能力。没有用户作答只能 not_assessed/unverified；用户说“懂了”只能 user_report。

**每组收束**：说明本组验证的能力、仍缺的关键证据和建议的可选下一步。“这组到这里，保存本组结果”使用 `session-checkpoint`，Session 保持 active；用户结束的是本组任务，不能推断为结束本次学习。没有用户继续意愿时，不接着自动发下一组题；不强制每个知识点各答一题，不追求全部练习正确。用户拒绝练习即停止出题，可以继续说明、Demo 或讨论。若用户已明确要求一个多步骤实战任务，可以继续完成这个任务，但仍尊重中途停止。

## 证据和保存

复用 [Session 流程](session.md)，所有教学事实通过 `session-checkpoint` / `session-finish` 批量追加。练习保留题目、实际答案、批改理由、验证形式、错误类型及逐项结果。来源引用必须能对照真实消息；没有独立证据的内容只能 unverified 或 user_report。

`teaching-context.criteria` 对每条标准显示 verified / needs_consolidation / user_reported / unverified，包含来源 Session、事件、原话和理由。它读取所选相关记录的有效事件，不只看 handoff.focus_ids。发生新作答时，最新有效的独立证据决定该标准当前状态；纯讲解、自报和空答案不覆盖旧验证。更正用 supersedes 撤回原判断，失效依据不能用来提速或宣称通过。Sprint 目标变更后，旧目标的证据不自动套用。

`teaching_state` 保存模式、速度、深度、是否练习、目前适用难度与理由；不是掌握评分。每次小组结束及时保存重要成果和未解决点，建议包含可选择的下一步；不必每道子问题单独保存。没有进展也能结束，不编造内容填充笔记。

## 两种收尾

**结束 Session**：用户说“今天到这，保存”“结束并记笔记”等，立即停教，通过 `session-finish` 保存实际事实和交接，读回状态与笔记路径后简短反馈。不追加题目、不要求纠错、不等待预计学时。只有停止而未要求保存，按既有 Session 授权规则处理，不擅自结束聊天或虚称保存。

**验收 Sprint**：若逐项证据充分，可以建议用户完成；不要重复检查已验证基础。若仍有关键缺口，明确指出用户可继续、跳过、结束 Session 或以后补充。只有用户要求完成 Sprint 才调用独立 transition，Session finish 和模式切换不会触发生命周期变化。AI 不因能力达标、时长够了或任务做完就擅自结束正在进行的聊天。
